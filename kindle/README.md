# Kindle Setup

The Kindle runs as a passive display: it pulls rendered PNG images from the
server over HTTP, shows them with `eips`, and keeps WiFi **off** between
fetches. Hardware buttons cycle screens; the center button does a hard
refresh (WiFi on → ask server to re-render → pull → WiFi off).

## Prerequisites

- Jailbroken Kindle (built for a Kindle 4 NT) with SSH access
- The server side set up first — see [`../server/README.md`](../server/README.md)
- The Kindle's IP (give it a DHCP reservation in your router)
- In the repo root `.env`:

  ```env
  KINDLE_HOST=192.168.1.xxx
  KINDLE_USER=root
  KINDLE_PASSWORD=...            # only if not using SSH keys (needs sshpass)
  DASHBOARD_SERVER_URL=http://<server-ip>:8090
  DASHBOARD_TRIGGER_URL=http://<server-ip>:8091
  ```

## Bootstrap

```bash
kindle/bootstrap.sh              # uses KINDLE_HOST from .env
kindle/bootstrap.sh 192.168.1.x  # or pass the IP directly
```

This copies everything in `payload/` plus a generated `config.sh` to
`/mnt/us/dashboard/`, installs the fetch cron job and a boot hook (so
dashboard mode survives reboots), stops the stock Kindle UI, starts the
button daemon, and pulls the first images. Re-run it any time; it's
idempotent.

## Daily operation

- **Left/right buttons**: previous/next screen
- **Center (select)**: hard refresh — enables WiFi, asks the server to
  re-render with fresh data, pulls images, disables WiFi (takes 1–3 min;
  a status message shows in the top-left corner)
- **Home**: redraw the current screen (clears e-ink ghosting)
- A cron job pulls the latest images every 30 min (WiFi cycled on/off)
- Keep the Kindle on USB power; the battery is only a buffer

## Maintenance

WiFi is off most of the time, so to SSH in either press the center button
and connect during the refresh window, or reboot the Kindle and connect
before the first cron fetch. Then:

```bash
# keep WiFi on until you're done
touch /mnt/us/dashboard/.keepwifi

# watch the log
tail -f /mnt/us/dashboard/dashboard.log

# leave dashboard mode (keeps WiFi on)
sh /mnt/us/dashboard/stop-dashboard.sh

# back to dashboard mode
rm -f /mnt/us/dashboard/.keepwifi
sh /mnt/us/dashboard/start-dashboard.sh
```

## If the buttons don't work

The keycodes vary between Kindle models. Calibrate once:

```bash
ssh root@<kindle-ip> sh /mnt/us/dashboard/identify-keys.sh
# press each button, note the codes, Ctrl-C
```

Edit the `*_CODES` lists in `/mnt/us/dashboard/config.sh` accordingly and
restart with `sh /mnt/us/dashboard/start-dashboard.sh`.

## Files (in `payload/`, deployed to `/mnt/us/dashboard/`)

| File | Purpose |
|---|---|
| `config.sh` | generated by bootstrap: server URLs, keycodes, intervals |
| `display.sh` | show current/next/prev image via `eips` |
| `fetch-images.sh` | WiFi cycle + pull images (+ optional server re-render) |
| `buttons.sh` | daemon mapping hardware buttons to actions |
| `identify-keys.sh` | interactive keycode finder |
| `start-dashboard.sh` | enter dashboard mode (also run by the boot hook) |
| `stop-dashboard.sh` | exit dashboard mode for maintenance |
| `setup-on-kindle.sh` | installs cron job + boot hook (run by bootstrap) |
